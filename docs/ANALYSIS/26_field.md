## 0. Headline

* **Entering and leaving (obs, §1).** The game is a chain of *sequences* driven by the admini task: `adminiChangeSeq`(id, packet, size, flag) copies a packet and `adminiUpdateTask_Call` calls entry `id` of **`sSequenceList 0x68F020`** (12-byte {call, exit, check} triples). The field layer owns three of the eight: **2 = field** (`K_Seq_CallField`: a field root for {major, minor, entry, ..}), **3 = field from an event** (`K_Seq_CallFieldEvent`: the ids come from an event PM file), **5 = the automatic dungeon** (`K_Seq_CallDungeon` → `K_FldDungeon_CreateTask`, which itself creates the field root of every Tartarus floor). 6 = battle (`btlStart`), 7 = shop, 4 = the Y_* map task, 1 = a test entry.
* **The field root (obs, §2).** `k_Field_CreateFieldRootTask` creates the "field root" kwln task (104-byte work) and clears **`sField 0x869F60`** (the task table of the field: camera, event, virtual pad, mini-map, enemy scheduler, panels … and the 16 × 16 Tartarus grid). `K_Field_UpdateFieldRootTask` is a 19-state loader (pack → field script → hit table → scene → camera → party → BGM → fade-in → **state 13 = running**); the load phase word `gp-0x4AA4` (0, 3, 1, 2) is `K_Fld_GetPhase`. A door / exit leaves through state 17 → `adminiChangeSeq(2, work + 76, 28)`, i.e. the next field is a new sequence-2 call.
* **The player (obs, §4).** Pad → `sub_1E05B0` (virtual pad) → `sub_1ADEC0` (move forward) on a 52-byte **collision controller** (`K_FldFrame_CreateCtlTask`); its update `K_FldFrame_UpdateCtlTask` applies the pending displacement in **three collision-checked thirds** (`K_FldFrame_HandleCollis` → RW collision world or the current Tartarus block's clump, triangle callbacks built on `K_FldFrame_IsPointInTriangle` and `K_FldFrame_ClosestPointOnSegment`), snaps to the ground with a ray from 200 (600 on random floors) above to 1000 below, and records the **800-unit grid cell** ((x + 400) / 800). The camera (`K_FldCamera_CreateFieldCameraControlerTask` / `K_FldCamera_UpdateFieldCameraControlerTask`) follows inside a dead-zone cylinder.
* **Tartarus (obs + der, §6).** The dungeon task holds the floor index; the floor table **`gFldDngFloorsData 0x867F60`** is `DATA/FIELD/TABLE/DUNGEONAT.BIN` byte for byte in the route (500 × 16 bytes: {major, minor, …}; random floors are **major 21..27 with minor 0**, one major per block, block entries at floors 2/17/65/115/165/215 = `dword_6833C0`). A random floor is a 16 × 16 grid of 800-unit cells in `sField + 72` whose cells name block resources `0x3000 + 16·z + x` (dumped at vblank 4560, §6.2). Shadows come from the k_encount floor readers (`sub_1D75F0/76E0` count and respawn), the Reaper (encounter 506) from a timer of 10 per visited cell, treasure boxes from `sub_1D77D0` + **`K_Encount_PickEncounter 0x1D78C0`, whose picks are item records** (a correction to 21_battle §3.3, §10).
* **Field → battle (obs + dynamic, §7).** A shadow contact is **not** a sequence change: the field event task `K_FldEvent_UpdateFldEventTask` (state 1) sees the contacted enemy (`gFldUnitsEc 0x86EDA0`), builds the same 52-byte packet `btlScrCmd_CALL_BATTLE 0x27D5E0` builds (party DatUnits, enemy encounter instance, background field = major + 200, room 1 when the encounter has none), tears down the camera / pad / panels, unloads the scene and calls **`btlStart` directly (state 14)**; the field root and the dungeon task stay alive. State 15 waits for the battle task, reloads the field pack and scene (16/17) and returns to exploration. `btlScrCmd_CALL_BATTLE` is the script path (sequence 6). The route shows it: at vblank 4700 the event work is in state 15, `gBtl = 0x1877830`, scene 251/1 (= 51 + 200), root and dungeon tasks alive.
* **Replaced (§9):** 15 pure leaves, 2,360 bytes, with pair tests that compare the whole register file: the field root / dungeon accessors, the random-floor predicate, the two collision primitives, the movement request, and the three encounter-task lookups.

## 1. Sequences: how the game enters and leaves the field (obs)

`adminiChangeSeq`(id, packet, size, keep) (`admini.c`): finds the admini task by name (`kwlnTaskGetTaskByName(gp-26608)`), sets work bit 0 (request), byte +9 = id, a one-frame delay byte +33 = 1, frees the old packet and copies `size` bytes of `packet` into a fresh `RwHeapMalloc` (+28, size byte +32); `keep` sets bit 2. `adminiUpdateTask_Call` (on the request, after the delay) moves +9 to the current id +8, records it in an 8-entry history (+10 index, +12.. ids), and calls **`sSequenceList[id].call(back, packet)`** (`0x27C55C`: `lui/addiu 0x68F020`, `3 × id` words, `jalr`); the check state `sub_27C650` (not read in detail) polls `.check`, and `.exit` belongs to the next change.

|---|---|---|
| 0 | 0 / 0 / 0 | none |
| 1 | `sub_27C9E0` / `sub_27CA10` / `sub_27CA40` | printf-only test entries |

### 2.3 Teardown
`K_Field_DestroyFieldRootTask`: frees the "NOW LOADING" task, stops channel 4, destroys all PC and EC field units (`sub_1D0330` / `sub_1D0390`), the PM reader, the exit table (`sub_1E7410`), the field pack; unloads the scene (`sub_3B5AB0`) unless the next sequence is 2/3/5; frees the battle-effect pack, resets the main camera frame, `sField.root = 0`, `RwFree(work)`.

### 2.4 The field task tree (obs; the draw half belongs to the rendering slices)
The draw tasks are not children of the root: `kwlnRootUpdateTask 0x198650` state 0 calls `K_SceneDraw_CreateTasks` once, which creates "scene draw ctl" with the shadow-map task (`sub_19D2A0`) and the nine field draw tasks of `22_rendering.md` §1 (priorities 2070, 2071, 2084, 2095, 4168, 4172, 4173, 4183, 4183); they draw only while scene resources exist (`K_SceneDraw_UpdateDrwOpcFldTask` walks the field resources with flag 2 → `K_FldSrc_DrawFieldOpaque`). The update tree under "field root" (priority 10 throughout, `kwlnTaskCreateWithAutoPriority`): the tasks of the `sField` table above, the collision controllers ("collision controler", one per moving resource, §4.2), the encounter tasks ("battle kosaka", §7.2), EPL effect tasks, the "automatic dungeon" task as the *parent* of the root on Tartarus floors (§6.1).

## 3. Map / scene loading (obs)

### 3.1 `MT_Scene_Load 0x3B5760` (`mt_scene.c`)
The scene record is `*(gp-0x57B0) = 0x95AFC0`: +0 s32 major, +4 s32 minor, +8 resource manager (`resrcMngCreate`), +12 flags (bit 0 = cache hit), +20 / +22 u16, +36 filter task. Same ids and not a random floor (major outside 20..28) → `"Scene data cashe hit!!"`, nothing reloaded; else unload (`sub_3B5AB0`), request the pack again, `sub_1B0A20(major, minor)` (requests the per-field files), filter task, the character / NPC lights (`MT_Scene_CreateResLightChar`, `sub_1A0A90`, `MT_Scene_CreateResLightNpc`, `sub_1A0EE0`). `MT_Scene_TryLoadFinish 0x3B5A10` → `sub_1B10F0` (5,776 B, `k_fldrc.c`; asserts 0x1B1F58 / 0x1B20B4): the field resources, the Tartarus layout (`sub_1BD450`, §6.2).

File names (strings in the ELF, obs): `field/pack/f%03d_%03d.pac` / `.fpc` (`sub_1B0870` / `sub_1B0950`), `field/pack/h%03d_%03d.bin` and `field/table/h%03d_%03d.bin` (exits, §5.3), `field/pack/f%03d.bf` and `field/script/*.bf` (field scripts), `field/pack/ns%03d_%03d.bf`, `nm%03d_%03d.bmd`, `n%03d_%03d.bin` (NPC script / messages / table), `field/env/f%03d_%03d.ENV` / `.CMR`, `field/data/f%03d_%03d.HBN` / `f%03d_%03d_%03d.FBN`, `field/map/f%03d_%03d.MAP`, `field/effect/DNG%02d.EPL`, `field/table/dungeonAT.bin` / `dungeonFES.bin` (`sub_1B7C40`: one or the other by its argument, `H_Cdvd_ReadSync`, size asserted < 0x2000 (`k_data.c` 170), copied to `gFldDngFloorsData`).

Scene resources are found by id: `MT_Scene_GetRes(id)` / `MT_Scene_GetResListHead(type)` (`0x3B5D10` / `0x3B5D50`), type = `id >> 10`, next resource at +248. Types used by the field (obs): 1 characters (the controller compares +296 with the PC unit's model), 3 objects, **12 Tartarus blocks** (id `0x3000 + 16·z + x`, collision clump at `+352 → +8`), **13 field hits** (quads at +284/+296/+308/+320, §5.2), 15 enemies (`0x3C00 + i`, snapshot 4560), 1024 (event task state 0).

## 4. The player: input, movement, collision, camera (obs)

### 4.1 Input
The virtual pad task `sub_1E05B0` (3,148 B; created in root state 12 with the hero's resource `*(0x8717F4) + 480` and model `0x8717F0`) turns the pad into a camera-relative heading (`atan2f`, `sinf`, `RwMatrixRotate`) and moves the hero with `sub_1ADEC0` (move forward: `mdlGetMatrix`, `RwV3dNormalize`); turning in place goes through the rotate task `sub_1E13F0` → `sub_1ADFF0`. `K_FldFrame_CtlMoveInDir` is the generic form used by the NPC-placement tasks `sub_1E3F10` / `sub_1E4BC0`. Pad words: `gPadFlags 0x7E094E` (topic 20 §4.1): bit 0x40 confirm (examine / open), 0x10 the camp menu (event task state 23), 0x80 a header script in the scenes `sub_1C6080` allows.

### 4.2 The collision controller (52 bytes; `K_FldFrame_CreateCtlTask`(parent, resource id, $f12 radius))
"collision controler" task, `K_FldFrame_UpdateCtlTask` / `sub_1AD630`. Work: **+0 state** (1 idle = accepts a move, 0 move pending, 2 off), +4 flags (bit 31 draw the debug sphere, bit 30 snap to ground, bit 28 no collision = radius 0, bit 27 frozen; `sub_1AD870` / `sub_1AD890` set / clear), +8 u16 resource id (type 1 → +10 = the unit's id, +12 the PC/EC field unit whose model is the resource's +296), +16 model, **+20..+28 f32 displacement**, **+32 f32 sphere radius** (`K_FldFrame_CtlGetSphereCollisRadius` / `K_FldFrame_CtlSetSphereCollisRadius`, the latter sets bit 28 for 0.0), +36, +40 s32 accumulated distance, **+44 / +48 grid cell x / z** (`K_FldFrame_CtlGetXGrid` / `K_FldFrame_CtlGetZGrid`).

`K_FldFrame_CtlMoveInDir`(task, dir, $f12 speed): only when idle: +20.. = dir × speed, +40 += (s32) speed (the unsigned conversion idiom for ≥ 2³¹), state 0. `K_FldFrame_UpdateCtlTask`: state 0 only (and not frozen): with bit 30 and collision on, a ray `K_FldFrame_Raycast 0x1ACC30` from the position + 200 (600 on random floors) to − 1000 sets the vertical displacement to land on the hit; then **three times**: displacement / 3, position + (0, radius, 0) → `K_FldFrame_HandleCollis` (adjusts the step), `mdlTranslate`; then +44 = (int)((x + 400) / 800), +48 = (int)((z + 400) / 800), the footstep update for resource ids with low 10 bits < 100 (`K_Footstep_Update 0x1DA020`), state 1.

### 4.3 Collision (obs)
`K_FldFrame_HandleCollis`(pos, step, resource id): field record `*(sField + 4460)` bit 0 → `sub_1AB390` (`RpCollisionWorldForAllIntersections 0x464020` with the triangle callback `sub_1AAF30`). Otherwise the mesh: on random floors and majors 51..78 the **current grid cell's block** — the cell u16 at `sField + 76 + 256·z + 16·x` (the controller's own cell, through the resource's +480 / +488 controller) names the type-12 resource whose `+352 → +8` is the mesh — else `*(sField + 4460) + 8`; then `sub_1ABD20` (clump atomics through `RpClumpForAllAtomics`, callback `sub_1ABCD0` → `sub_1AB640`, which transforms by the atomic's LTM). Both triangle tests use **`K_FldFrame_IsPointInTriangle`(point, verts[3], normal)** — the crossing-number test in the plane the normal's largest component drops (x → (y, z), y → (z, x), z → (y, x); ties drop x then y): every edge whose s-range contains the point (half-open) toggles the result when the point's u is below the edge's u at that s — and **`K_FldFrame_ClosestPointOnSegment`(out, p, a, b)**: t′ = (p − a)·d with d = b − a, out = a (t′ ≤ 0), a + d·t′/|d|² (t′ < |d|²), b otherwise, the dot products through ACC in the compiled order.

### 4.4 Camera (obs)
`K_FldCamera_CreateFieldCameraControlerTask`(parent): 208-byte work, a new RW frame (+12) inserted between the main camera's frame and its parent (+16), `K_Draw_CreateCylinderTask` (the debug cylinder). Update `K_FldCamera_UpdateFieldCameraControlerTask` (1,984 B), modes +8 = 0/2/5 follow: target = the player resource (+204, `sub_1D5F30` sets it) position + offset (+20..+28); when the horizontal distance from the camera position exceeds +32 or the height difference exceeds +36 / 2, the frame is moved (`RwFrameOrthoNormalize`) — a dead-zone cylinder of radius +32 and height +36; mode 2 also re-aims (`sub_1A1210`). The rotation tasks `sub_1D6270` / `sub_1D6630` (created by the root and the virtual pad) turn it.

## 5. Events, NPCs, field hits, exits (`k_event.c`, `mt_evt*.c`; obs)

### 5.1 The field event task `K_FldEvent_UpdateFldEventTask` (20,296 B, 33 states)
Created by `K_FldEvent_CreateTasks` in root state 12 (with the draw-command task `sub_1CD710`). Every frame before the switch it handles the game-over / forced-exit condition (`*v12 > 0`, no battle, `sub_45AF40() == 0`: fade 90, flag 5149, state 29) and two count-downs (+248, +252). **State 1 = exploring**, in this order:

1. **Shadow contact**: `sub_453460()` (the enemy-think layer's contacted index, bit 15 clear) → `v12[9] = gFldUnitsEc + 448·i`; if its genus is alive, the battle packet is built (§7.1), pad / camera / panels / footstep paused, the hero's attack animation → **state 4** (player first) — the ambush path is state 6.
2. pad 0x80 in an allowed scene → header script (`scrCreateTaskFromHeader(10)`), pause, state 2 (wait for the script, unpause, back to 1).
3. pad 0x10 with flag 369 clear → camp menu: destroy pad / mini-map / party panel, pause the rest, state 23.
4. the held weapon type (`datCalcGetHeldWeaponType`) and its 24-byte record (`gp-0x4A5C`), the nearest interactable (`sub_1C6A20`) → `v12[9]`.
5. **Field hit** under the hero (`K_FldEvent_IsUnitNearFldHit`, random floors only): show the prompt (+224); with 0x40 → the dungeon script memory procedure 0 (stairs / transporter), state 2.
6. random floors: resource 11263 within 200 → procedure 1.
7. **treasure**: the 4 × 4-cell bucket of the hero (`dword_86B180 + 4·(49·bx + 196·bz)`, ids at `dword_86B1E0`) within 200 of an unopened box → the box script (`gp-0x4AC8` / `gp-0x4ACC` memory, procedure 0), the box marked open, state 2.
8. NPCs (`K_FldEvent_FindInteractableNpc 0x1C74C0`, not read in detail: `K_FldEvent_IsPosWithinFov 0x1C6200`, animation ids, `mdlLookAt*`).

The other states: 3 = an exit (§5.3), 4–18 the battle (§7.1), 23.. the camp menu, 29–31 fades / game over, 32 the exit wait. `K_FldEvent_IsUnitHero` compares with **`gFldUnitsPc 0x8717A0`** (the hero is PC unit 0).

### 5.2 Field hits
