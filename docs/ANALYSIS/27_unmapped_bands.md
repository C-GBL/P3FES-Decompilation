# 27 — The unmapped EE bands: what lives in 0x1E0000–0x26FFFF, 0x2A0000–0x2BFFFF, 0x2E0000–0x2EFFFF, 0x320000–0x34FFFF, 0x360000–0x38FFFF, 0x3C0000–0x45FFFF

_Phase 5 mapping pass for wave 10 (no game code). Database: `ida/work_bands.i64`, one copy of the master taken at the start and opened headless with idalib, never saved. Every address is an EE virtual address. Tags: **obs** = read from the instructions, the ELF bytes or a replay snapshot; **der** = counted / derived from obs by a script; **inf** = inferred. Names are `symbols/functions.json`'s (nearly everything here is `sub_*`); community hint names are not used (ADR-0009) — the IDA copy carries them, so every name below was checked against `functions.json`. The decompilation queue for these bands is `docs/ANALYSIS/queue_bands.txt`; proposed names with evidence are in `symbols/deltas/bands.sym` (not imported)._

## 1. Method (what was run)

1. `tools/ours/ida/rendering_dump.py` on the copy → `funcs.jsonl` (callers, callees, code-referenced function pointers, `jalr` count, hardware/VU0/MMI census) for all 14,500 functions; a sibling read-only script → every function's data references with the string at the target (`K_Assert` file names, task names, file paths).
2. **Task anchors.** For every call site of `kwlnTaskCreate 0x194B20`, `kwlnTaskCreateWithAutoPriority 0x194B80`, `kwlnTaskInit 0x194C50` and `kwlnTaskInitEx 0x194E10` (303 sites, argument registers per `game/include/p3fes/game/task.h`), a constant tracker over the preceding 40 instructions recovered the name string and the update/destroy pointers: **288 sites with a name**; 89 sites have the creator or the update function in these bands (83 named).
3. **Live tasks per route.** The kwln lists (`0x7CE064/70/7C`) and every stale 0x68-byte task record in the heap (name + `name_sum` at +0x18 must agree, update pointer at +0x34 a function start) were read from 15 replay snapshots: M1 `v_m1`; title `r3_title_sky3100/3315` (a title run on the same boot path the dorm route takes: `to_dorm.txt` presses Start/Cross through the logo, movie and title from vblank 549); dorm `dorm_l1_4650`, `dorm_m4_4762`, `dorm_replay_4900`, `dorm_replay_5200`, `dorm_line2_5300`; battle route `b_3500`, `b_5800`, `battle_ref_6150` (the gate) and `b_6300/6700/7200` (after the gate's stop).
4. **Static reach (der).** From the update functions found in step 3, a closure over direct calls and tail jumps (no `jalr`, no tables): M1 1,530, dorm 2,498, battle 3,446 functions. Adding code-referenced callbacks merges everything (5,121 for every route) and adding table dispatch pulls battle-panel code into the dorm route, so only the direct-call closure is used, and it under-counts table-dispatched code (camera states, effect types). A return-address residue scan of the snapshots was tried and dropped: outside the main thread stack (`0x1F60000+`, ~30 functions) its hits are coincidences in heap data.
5. Data tables: runs of ≥ 3 function pointers in `0x5A0000–0x7CDE80` pointing into a band (1, 7, 6, 11, 5 and 37 runs for the six bands), and `sScrCommandTable 0x7B92B0` (60 of its 488 non-null entries point here).
