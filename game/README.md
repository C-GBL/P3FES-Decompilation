# `game/` — hand-decompiled game code (Phase 5)

_GOAL.md Phase 5: "Replace recompiled blocks with readable C++ in `game/`, starting with: file system
layer, BF script VM, BMD message rendering, menu/UI, then battle. Each replaced function must pass
the trace diff before the recompiled version is removed. Keep the IDA names and the `game/` function
names identical."_

## How a function moves from `recomp/generated` to here

1. Pick it from the queues (`docs/ANALYSIS/queue_*.txt`, the topic docs under `docs/ANALYSIS/1x_*.md`
   explain what it does) and read the recompiled body in `recomp/generated/fn_*.cpp` next to the IDA
   disassembly (`ida/p3fes.i64`; Ghidra's decompiler is a reading aid, never a source of names).
2. Write it under its IDA name in `namespace p3fes::game` (`include/p3fes/game/<module>.h`,
   `src/<module>/<file>.cpp`), taking `EEContext&` first and plain C++ types after it; guest memory
   goes through `include/p3fes/game/guest.h` (`load`/`store`/`ptr`/`cstr`). Mirror the recompiled
   body's virtual time with `guest::enter` (entry check point + first block), `guest::charge` per basic
   block the path executes, and `guest::backedge` where the recompiled loop had its back-edge check
   (ADR-0013; the `ctx.cycles += N` lines of the generated function give N). This keeps every run
   byte-identical to the fully recompiled program and goes away in Phase 6 when timing moves to the
   wall clock.
3. The recompiled program's entry point `p3fes::recomp_gen::fn_<name>_<addr8>` (the dispatch table and
   every generated call site use it) is generated from `replaced.txt` (since 2026-10-29,
   `game/forwarders.cmake`, `recomp/README.md` "Forwarders"): a register-ABI body
   `void <name>(EEContext&)` needs nothing more. A typed C++ function needs a shim in its file, in
   `namespace p3fes::recomp_gen`, that takes the arguments from `$a0..$a3` (`guest::arg32`) and writes
   the result to `$v0` (`guest::ret32`/`rets32`), plus a `0x<start> <name> -` row in `forwarders.txt`.
4. Add `<hex start> <IDA name>` to `replaced.txt`, re-emit with `--replace game/replaced.txt`
   (`recomp/README.md` "Replacements") and rebuild. The emitter keeps the old body under
   `fn_<name>_<addr8>__recomp`.
5. Gate it: a pair test in `tests/game/test_replacements.cpp` runs the hand-written function and the
   `__recomp` body on identical guest machines (same result, callee-saved registers, memory outside
   the dead stack, cycles, check points) on randomised inputs; then the whole-program gate, the
   deterministic dorm replay (`BUILDING.md` "Scripted path into the game"), must stay byte-identical
   (`frame.png`, `eeMemory.bin` outside the dead stack) and M1/M2 too. Record both in the commit.

Functions with mid-body entries (23 entries in 21 functions, the libc/CRI band) are replaced as a whole since slice
`finalD`: the `replaced.txt` row lists the entries (`0x526238 vfprintf @0x5262b0`), `game/` defines the function and one
`<name>_at_<pc8>` per entry (each its own forwarder `fn_<name>_<addr8>_at_<pc8>` and its own pair), and the regions
the entry points share are `static` bodies called where the flow enters them (recomp/README.md "Replacements").

`guest::StackFrame` (`guest.h`) is for functions whose original handed stack buffers to callees: it
lowers `$sp` by the original frame size for the function's lifetime and gives the guest address of each
buffer, so recompiled callees (`strcpy`, `strcmp`) read and write the same guest bytes as before and a
function that reads stale frame bytes (`H_Cdvd_SplitPath` without a `\`) does exactly what the original
did. Register spill slots are not written; `tests/game/` compares the buffer bytes of both frames.

`replaced.txt` is the authoritative list; `tests/game/CMakeLists.txt` names the same starts for its
emission and must be kept in step.

## Pair tests that observe the hardware

A function whose callees touch hardware registers (the DMA packet layer of the rendering path:
`_rwDMAOpenVIFPkt` and friends, kept recompiled behind a direct call) leaves more than an `Outcome`:
the register accesses it caused, what it did with the values those reads returned, and guest memory
outside the arena. `tests/game/pair_harness.h` has an opt-in variant for those (existing tests are
untouched):

* `HwCheck` says what to serve and compare: `regs` (physical address -> value; reads return it, writes
  update it), `reads` (a per-register script: the k-th read of an address returns the k-th value, e.g.
  `D_STAT` without bit 8 twice to make the BC0F wait loop), `ranges` (main RAM or scratchpad ranges such
  as the RW globals and the DMA buffer, restored before the second run and compared), `compare_spr` (the
  whole 16 KiB scratchpad at 0x70000000, always restored), `compare_bus` (the access log: direction,
  width, physical address, value; and VU control writes), `gpr_mask` (registers compared in all 128 bits;
  `kAllGprs`), `compare_hilo` (HI/LO of both pipes, SA), `compare_checkpoint_regs` (the whole register
  file -- GPRs in 128 bits, HI/LO, SA, FPRs, FCR31 -- and the cycle count at every check point, in order),
  `compare_dead_stack` (the frames and spills below `$sp`) and `gpr_in` (registers set after the random
  context: arguments 5..8 in `$t0..$t3`).
* Why the check-point registers matter: a check point may preempt the thread, and the kernel then saves
  the full context at `$sp - 0x280` in guest memory (`KernelOptions::context_frames`); switching syscalls
  later in the caller do the same with whatever the function left in its scratch registers. Those bytes
  are compared by the whole-program gates (the first render_im2d gate run differed in 17-35 stack bytes
  this way with only `$v0` and the callee-saved registers reproduced). A function whose scratch registers
  are live across its check points, or that returns with scratch registers its callers never overwrite
  before a syscall, has to be register-faithful at every check point, call and return.
* `run_pair_hw(m, hand, recomp, args, seed, what, hw, resets)` runs both bodies, each on a fresh
  `HwHooks` (a `ScriptedBus` that logs like `rt_test::RecordingBus` and serves the script, then `regs`,
  then RecordingBus's address pattern) and compares the `Outcome`, the callee-saved registers' upper
  halves, syscall/trap counts and everything `hw` asks for; `HwPair` keeps both runs (bus logs included)
  for documented-rule checks (`count_access`). `same_frame_bytes(HwPair, ...)` compares dead-stack bytes.

The bus performs no transfer: a fromSPR copy is a sequence of register writes in both runs, so the
scratchpad and the DMA buffer are compared as the functions left them. `tests/game/test_render_im2d.cpp`
is the first user.

## Pair tests with stand-ins

Callees a pair cannot run for real -- the heap (H_Malloc / H_Free, the RenderWare memory functions behind the slots
0x960178..0x96018C, newlib malloc / free / calloc / realloc), printf / sprintf, the H_Cdvd file layer, or any callee
the test library does not emit -- are served by deterministic stand-ins (`tests/game/stand_ins.h`, `stand_ins.cpp`),
opt-in per test:

* **How both bodies meet them.** The test library is emitted with `-DSTAND_INS` (`tests/rt/emit_units.cmake`): every
  stub of a function it does not emit calls `stand_in_or_missing(ctx, va)` (no stand-in installed for `va`: the
  same `rt::missing_function` stop as before), and each emitted function listed in `_stand_in_hooks`
  (`tests/game/CMakeLists.txt`: the heap entry points, sprintf, vsprintf) first asks `stand_in_hook`. The hand-written
  body reaches the generated symbol through `jal` / `guest::call`, the recompiled body through its `jal` or
  `rt::lookup_func` (slot calls), so both meet the same stand-in. Nothing changes for a test that installs nothing
  (every existing test file passes unchanged).
* **What a stand-in does.** `StandIns::serve` records the call (`StandInCall`: address, `$ra`, `$a0..$a3`,
  `$t0..$t3`, result, formatted text or path, size), runs the callee's entry check point (so `compare_checkpoint_regs`
  sees the registers at the call), charges a fixed cost, does its work on guest memory, sets `$v0`, and overwrites
  `$at`, `$v1`, `$a0..$a3`, `$t0..$t9` with a per-call pattern.
* **The parts.** `GuestHeap` (16-byte first fit over the arena 0x1C00000..0x1F00000, deterministic addresses, no guest
  header; `install_h_malloc` / `install_rw` / `install_libc`; `write_rw_slots` puts the retail function addresses in
  the slots; `read_snapshot`, `copy_from_snapshot`, `h_malloc_blocks`, `reserve` for real heap state); `guest_format`
  / `install_printf` / `install_sprintf` (newlib's formatting over EE varargs: the arguments after the fixed ones in
  `$a1..$a3` / `$t0..$t3`, then 8-byte stack slots from the caller's `$sp`; equal to the recompiled sprintf on
  3,000 random integer / string formats); `FakeCd` (H_Cdvd_Request / Update / ReadSync / Destroy with the retail
  node layout, list behind sCdvdListHead and sCdvdCache registration through the hand-written H_Cdvd_AddFile; files
  from `extracted/` DATA, BTL, BGM, or record-only); `StandIns::install_recorder` for anything else.
* **The pair.** `run_pair_si(m, hand, recomp, args, seed, what, hw, setup)` builds a fresh `StandInWorld` per run
  with `setup` (default `install_standard`), adds the heap arena to the compared and restored ranges unless a range
  already covers it, runs `run_pair_hw`, then requires equal call logs (`expect_same_log`), equal live heap blocks and
  equal request nodes. `tests/game/test_standins_demo.cpp` is the first user.
