## Facts that constrain later phases (from the IDA pass)
- **The recompiler decodes raw instruction words, never IDA's rendered items** (tightens ADR-0004): IDA fuses 16,389 words into macro items (`li` 8 B, `%hi/%lo` pairs, `uld/usd`, `dli`), misrenders 201 `bc0f` as `mfthc1` and 9 `pexew` as `pexow`, and shows every VU0 op as opaque `cop2`. IDA supplies boundaries (`functions.json`, chunks), switch tables (`jumptables.json`) and names; the bytes come from the ELF. One word in `sub_46BFB0` has no IDA item head; 1,553 data words inside chunks decode as valid instructions — settle per site before skipping them.
- **Metrowerks, not gcc.** Prologue/epilogue idioms, switch-table shapes and struct-passing follow MW MIPS C 2.4.1; the *register* ABI is still the SCE EE ABI (sce libs must interoperate). Phase 3's instruction-level recompiler is unaffected; Phase 5 hand-decompilation must expect MW idioms. Source-file → address-band map in `docs/ANALYSIS/03` (`kwln*`, `k_*`, `btl*`, `scr*`, `mt_evt*`, `fcl*`, `G3_2D*`) is the subsystem map.
- `runtime/include/p3fes/syscalls.h` agrees on every shared number, but the ELF uses ~60 numbers the ps2sdk header lacks (0x4A–0x5B TLB/Copy/GetEntryAddress, 0x60–0x6F, 0x72, 0x75, 0x7B, 0x7D, 0x80–0x83, 0xFC–0xFF; full list in `02_syscalls.md`) and the negative `i*` form for `iWakeupThread` (−0x34). Runtime needs **named traps** for all of them, not a silent default.
- 19,008 orphan "code" items are mis-disassembled VU microcode / packet data — expect VU1 blobs and GIF/VIF tables inside the data band; they must be carved, not disassembled as EE code.
- **Recompiler boundary rules (from the Ghidra cross-check):** (a) **54 mid-body `jal` targets** — functions entered past their start (MW tail-jump splitting, e.g. `vfprintf 0x526238` whose body `0x5262B0` is also called directly by `sub_528920`): the emitter needs per-function multiple entry labels or split-at-entry; (b) **11 called addresses with no IDA function** (`0x4501B0` 2,432 B from `sub_44BEB0`, `0x241910`, `0x4FBF48`, `0x46B8E0`, `0x5244C0`, … full list in `06`) — create them on the master before forking; (c) **jump tables come from IDA only** — export switch tables next to `functions.json`; (d) exit stub `0x100210–0x100217` lies outside `start`; (e) consume IDA `Chunks()`, not summed sizes, for the 172 multi-chunk functions.
- **Static image is complete (topic 13, high confidence):** the EE never executes user code outside `0x100000–0x5A1400`. 0 write xrefs into the code band, 0 callers of `sceSifLoadElf*`/`LoadExecPS2`/`ExecPS2`, `sceCdRead` has 2 CRI callers with caller buffers, 553 `jr` switch tables all file-backed, 0 EE ELFs/MIPS code in 12,042 game files. "Battle/field modules" are statically linked. The recompiler may assume a closed function set — with the residual risk of **function pointers originating from file contents** (tracediff `jalr` targets vs `functions.json` on first entry to each scene).
- **Kernel-patch payloads, resolved:** the data-band cluster `0x77F710–0x780A08` is libkernel code copied *out* of the image — `InitTLBFunctions 0x50CC78` (`0x330` B → `0x80075000`), `InitExecPS2 0x50D780` (`0x7A8` B → `0x80074000`), `InitAlarm 0x50DB38` (`0x740` B → `0x80076000`, `0x28` B → `0x82000`), each followed by `FlushCache(0)`, `FlushCache(2)`, `SetSyscall` from tables `0x77F8E8`/`0x780380`/`0x780B08`. **Never recompile**; HLE the patched syscalls (topic 12). All other 28 `FlushCache` sites are `FlushCache(0)` before DMA → no-op in the runtime.
- **15 `jr $reg` sites are RenderWare vtable/global tail calls** → emit as indirect tail calls with a hard error (+VA) on unknown targets. **70 callbacks** reached only via `li reg,<code addr>` function-pointer stores were uncarved by IDA (created from topic 13's delta). VU1 microcode bands by NOP signature: `0x5A2000–0x5CA000`, `0x6B6000–0x77A000` (topic 14 verifies).
