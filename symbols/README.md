# symbols/ — single source of truth for SLUS_216.21 names

Generated by `tools/ours/ida/export_symbols.py` from `ida/p3fes.i64`; never hand-edit. To add or
change a name, set it in IDA (or in `tools/ours/ida/names_manual.txt`) and re-export. `game/` code
in Phase 5 must use these names verbatim.

## `p3fes.sym`

```
# p3fes.sym  SLUS_216.21 (Persona 3 FES NTSC-U)  ELF SHA-256 <sha256>
# generated <timestamp> by tools/ours/ida/export_symbols.py from ida/p3fes.i64 (processor r5900l)
# <addr8> <size8> <F|D|L> <name>
00100008 00000208 F start
00100220 00000010 F _sceExitThread
007cde80 00000320 D bss_start
```

One record per line, sorted by address, fields separated by single spaces:

| Field | Meaning |
|---|---|
| `addr8` | virtual address, 8 lowercase hex digits (load base `0x00100000`) |
| `size8` | bytes, 8 hex digits. `F`: sum of all function chunks (IDA `Chunks()`); `D`: IDA item size; `L`: `0` |
| kind | `F` function (every IDA function, including auto `sub_*`/`nullsub_*`, so Phase 3 has complete boundaries), `D` data item with a user-assigned name, `L` code label with a user-assigned name |
| `name` | IDA name. Only functions may carry IDA auto names; `D`/`L` records are user names only (IDA auto/dummy names such as `aString`, `jpt_*`, `def_*`, `off_*` are excluded) |
| tags (optional, after the name) | `flirt` = name from a FLIRT signature match (IDA `FUNC_LIB`), not analysis evidence. `source=<src>` = name adopted from a community source under ADR-0009: either permissively licensed (`fes-pc-recomp`, MIT; see Attribution) or analyst-verified and promoted (`verified` line in the IDA hint comment, evidence in `docs/ANALYSIS/`). Unverified community hints never appear here: the exporter writes such functions as `sub_<ADDR>` and drops hinted data names (`ida/logs/export_hints_withheld.txt`, gitignored). |

Naming conventions in use:

* `_sce<KernelName>` — thin EE kernel syscall wrapper (`li $v1,N / syscall / jr $ra / nop`), name from
  ps2sdk `syscallnr.h` (`_sceFlushCache`, `_sceiSignalSema`); header names already starting with
  `sce` get only the underscore (`_sceSifSetDma`, `_isceSifSetDma`). Duplicate wrappers get IDA's
  `_0`, `_1` suffix. See `docs/ANALYSIS/02_syscalls.md`.
* `*_candidate` — analyst inference not yet confirmed by trace (e.g. `main_loop_candidate`).
* Everything else: plain IDA names set during analysis; evidence in `docs/ANALYSIS/`.

## `functions.json`

Compact array for tooling (`recomp/`): `[{"a":"0x100008","s":520,"n":"start"}, ...]` — `a` start
address (hex string), `s` total size in bytes, `n` name. Same function set as the `F` records.
